# Profiler 实施计划

> 执行约束：先写失败测试，再实现；所有提交信息使用简体中文；默认在当前 `main` 分支；不引入 SQL 或 Redis Cloud。

## Task 1：领域 DTO 与 MONITOR parser

文件：`src-tauri/src/domain/observability.rs`、`src-tauri/src/redis/observability.rs`、`src-tauri/tests/domain.rs`。

先增加 `StartProfilerInput`、`StopProfilerInput`、`ProfilerEvent`、`ProfilerStatusEvent` 和校验测试；再增加 `parse_monitor_line` 测试，覆盖时间、db、source、引号参数、转义参数和 malformed reply。实现时只返回固定 `INVALID_INPUT`/`COMMAND_FAILED`。

验证：`cargo test --manifest-path src-tauri/Cargo.toml profiler`。

## Task 2：Profiler service 与连接生命周期

文件：`src-tauri/src/redis/connection_manager.rs`、`src-tauri/src/redis/observability.rs`、`src-tauri/tests/redis_integration.rs`、`src-tauri/Cargo.toml`（复用 futures-util）。

先增加未打开连接返回 `CONNECTION_FAILED` 的测试和 ignored MONITOR 集成用例；再实现 `ProfilerManager`、`get_async_monitor`、后台任务、事件发送及 open/close/select cleanup。每个连接只保留一个任务，停止匹配会话幂等。

验证：`cargo test --manifest-path src-tauri/Cargo.toml connection_manager::tests`，集成用例只编译，真实 MONITOR 流显式 ignored。

## Task 3：Tauri commands 与 typed bridge

文件：`src-tauri/src/commands/observability.rs`、`src-tauri/src/commands/mod.rs`、`src-tauri/src/lib.rs`、`src-tauri/tests/commands.rs`、`src/lib/types.ts`、`src/lib/tauri.ts`、`src/lib/tauri.test.ts`。

增加 `start_profiler`/`stop_profiler`，注册事件名称并测试 IPC 参数形状和错误码。保持 `AppHandle` 注入的 MockRuntime 限制记录在测试边界中，生产 handler 使用默认运行时编译验证。

## Task 4：前端 Profiler 工作区

文件：`src/features/observability/ObservabilityPage.tsx`、`observabilityState.ts`、测试、`src/App.tsx`、`src/styles.css`。

在现有运维观察页增加 Profiler tab；启动前显示性能提示，显示时间/db/source/args，提供停止和清空视图；事件按 connection/session 过滤，最多保留 10,000 条，切换连接和卸载时解除 listener/停止会话。

## Task 5：回归与交付

执行 `cargo fmt --check`、Rust 全量测试、前端全量测试、构建、非 Cloud 扫描和差异检查；更新 README、`docs/non-cloud-scope.md`、`findings.md`、`progress.md`、`task_plan.md`。真实 MONITOR 测试若有副作用或权限风险不执行，并记录原因。
